# MarkText Rust 复刻实施计划（路线 A：Fork 上游改造）

> 版本：v2.0（grill-me 拷问补全版）· 日期：2026-10-23
> 目标：以 Rust 最新稳定版 + eframe/egui 复刻 MarkText（Electron 版 v0.24），不含任何 WebView 技术栈
> 基座：上游项目（MIT 协议，Rust + egui 0.34.2，已具备 WYSIWYG 内核）
> 状态：**待主人审核** —— 文中所有「推荐结论」均为我方预填，可在审核时逐项推翻

---

## 一、总体策略

**Fork 上游 → 裁减非目标模块 → 重塑 UI 为 MarkText 外观 → 迭代对齐 Muya 交互细节。**

核心理由：上游基座已具备 WYSIWYG 内核（RenderedEditSession：块级渲染/编辑切换、commit-boundary undo、ropey 缓冲）、comrak 解析（652/652 CommonMark、670/670 GFM）、原生 Mermaid（11 种图表）、hayro 纯 Rust PDF 导出、syntect 高亮、i18n。原计划最高风险项（自研 WYSIWYG 内核）被消除，总工期从 12–14 周压缩至约 6 周。

**合规**：MIT 协议，fork 保留 LICENSE 与版权声明；衍生作品继续以 MIT 发布。

## 二、决策树拷问记录（每问附推荐结论）

### 分支 1：仓库形态与命名

**Q1.1 Fork 放哪里？独立仓库还是并入 marktext-rust monorepo？**
→ 推荐：**独立仓库**，clone 至 `~/MyDev/mdoxide`，添加 `upstream` remote 指向 上游原仓库。理由：上游迭代快（v0.3.1 进行中、LSP 规划中），独立仓库可 rebase 上游修复；marktext-rust 本仓库保持为 Electron 原版的参考源码，不混入。

**Q1.2 新应用叫什么名字？**
→ 推荐：工作名 **MDOxide**（应用 ID `dev.mdoxide.app`，配置目录 `~/.config/mdoxide/`）。理由：避免与 MarkText 商标混淆，同时暗示血缘；发布前可再议。图标首版沿用占位，M5 阶段再设计。

**Q1.3 Fork 后第一个提交做什么？**
→ 推荐：先打基线 tag（`baseline-upstream-0.3.x`），再单独一个提交完成改名/改 ID/改配置目录，保证后续 `git diff upstream/master` 时品牌改动清晰可隔离。

### 分支 2：裁减策略

**Q2.1 裁掉哪些模块？**
→ 推荐裁掉：**集成终端（portable-pty/vte）、CSV/TSV 编辑器、JSON/YAML/TOML 树状查看器、Live Pipeline、LSP 相关代码、Git 集成（git2，主人已确认取消）**。保留：文件树、跨文件搜索、会话恢复、Mermaid、导出、i18n、CSV 只读预览。

**Q2.2 删除还是 feature 门控？**
→ 推荐：**feature 门控**（`terminal`/`csv-edit` 等 feature 默认关闭）。理由：减少与上游的 merge 冲突；若上游修复了这些模块的 bug 仍可同步。代价是 Cargo.toml 复杂度上升，可接受。

**Q2.3 裁减后依赖瘦身到什么程度？**
→ 已确认（主人拍板）：裁掉 portable-pty、vte，**git2 一并裁掉**（Git 集成取消，严格对齐 MarkText 功能集）。预期 release 二进制 ≤ 20MB。

### 分支 3：UI 重塑（核心改造）

**Q3.1 自绘无边框窗口在 KDE Plasma 6 / Wayland 下可行吗？**
→ 推荐：**默认自绘标题栏 + 设置项可切回原生装饰**。理由：eframe 的 `ViewportBuilder::with_decorations(false)` 在 Wayland 下依赖 compositor 支持 CSD，KDE 支持良好，但 M2 第一周必须真机验证窗口拖拽/缩放/最大化；若翻车则默认原生装饰（MarkText 本身也有系统标题栏模式，不违背复刻目标）。

**Q3.2 侧边栏三页签怎么实现？**
→ 推荐：基于 上游现有 SidePanel 改造，加页签栏（大纲 TOC / 文件树 / 搜索）。TOC 数据源：comrak AST 提取标题树，与编辑器共享 AST 缓存避免二次解析。宽度拖拽 + 记忆（存 toml 配置）。

**Q3.3 主题体系怎么移植？**
→ 推荐：两层主题——UI 层用 egui `Visuals`（亮/暗），编辑器层自定义 `EditorPalette` 结构体（标题色、引用条色、代码块底色等），从 MarkText `static/themes` 的 CSS 变量逐项取色移植。首版内置 3 套：Light（对齐 MarkText 默认白）、Dark、Graphite。主题文件用 toml 外置，用户可扩展。

**Q3.4 编辑区排版如何对齐？**
→ 推荐：居中栏宽默认 720px（可调 600–900），段距/标题字号按 MarkText 默认主题 CSS 实测值换算（px → egui points 1:1）。

**Q3.5 中文字体怎么办？**
→ 已确认（主人拍板）：`fontdb` 扫描系统字体，**内置思源黑体（Source Han Sans / Noto Sans CJK SC）作为中文兜底**，接受体积代价。

### 分支 4：Muya 交互对齐

**Q4.1 「光标所在块显示源码标记」如何实现？**
→ 推荐：在 RenderedEditSession 的块渲染层加 Inline Marker 模式——块获得焦点时，该行 LayoutJob 重建，把 `##`、`**`、`` ` `` 等标记以 40% 透明度插入渲染流；失焦恢复。不切换为纯源码编辑（与 上游现有块编辑机制兼容最好）。

**Q4.2 气泡格式工具条？**
→ 推荐：egui `Area` + `Order::Foreground` 浮动窗，选区非空时锚定选区上方。按钮集：B / I / S / 行内代码 / 链接 / 高亮。操作直接改写 rope 源文本（包裹标记），走 commit-boundary undo 保证撤销粒度正确。

**Q4.3 打字机/专注模式？**
→ 推荐：打字机模式 = ScrollArea 滚动偏移使光标行恒定垂直居中（在 上游 Zen 模式基础上加 scroll 钩子，工作量小）；专注模式 = 非当前块透明度降至 35%。两者独立开关。

**Q4.4 快捷键冲突怎么取舍？**
→ 推荐：键位表以 **MarkText 为准**（Ctrl+B/I、Ctrl+1~6、Ctrl+Shift+V 纯文本粘贴等），上游独有功能（Run 代码块等）保留但重排键位。键位 toml 可覆盖。

### 分支 5：导出与扩展内容

**Q5.1 PDF 用 hayro 还是 typst？**
→ 推荐：**先验证 hayro 现状**（M4 第一周走查：中文、代码块、表格、Mermaid 嵌入）。注意 hayro 本质是 PDF 渲染器，上游实际是排版后渲染导出，质量需实测；不达标则换 `typst` 作为生成后端（md → typst 源码 → PDF，质量上限更高，代价是较大依赖）。决策点设在 M4 走查报告之后。

**Q5.2 数学公式？**
→ 已决策：采用 **RaTeX**（`ratex-*`，纯 Rust 的 KaTeX 兼容实现）。集成方式：`ratex-svg` 输出自包含 SVG（`embed_glyphs=true`），经 `resvg` 栅格化为纹理并按 `(公式, 主题, DPI)` 缓存；`ratex-pdf` 可在导出阶段复用。
→ 备选（仅当同时重做 PDF 导出时）：`typst`；`mathtex`（XeTeX 移植）排版更精细但集成成本更高。
→ 不采用：任何 JS/WebView 方案、运行时调用系统 TeX 二进制。

**Q5.3 Mermaid 保留到什么程度？**
→ 推荐：全量保留 上游的 11 类原生渲染 + 插入模板。这是相对 Electron 版 MarkText 的**超越点**（原版依赖 JS 渲染）。

**Q5.4 PlantUML？**
→ 推荐（P3）：首版不做，源码块原样展示。不进里程碑。

### 分支 6：工程与发布

**Q6.1 测试策略？**
→ 推荐：内核层（rope 编辑、undo、AST 缓存）必须单元测试覆盖改动路径；UI 层用 egui 快照测试（`egui_kittest`）覆盖标题栏/侧边栏/气泡条三大新组件；M3/M4 验收走人工走查清单。

**Q6.2 上游同步频率？**
→ 推荐：每个里程碑结束时 rebase 一次 upstream/master；冲突高发区（Cargo.toml、编辑器内核）由 feature 门控和模块隔离控制。

**Q6.3 打包优先级？**
→ 已确认（主人拍板）：**Linux RPM + DEB + Windows NSIS**，macOS 不做。Linux 优先验证（主人环境 Fedora/KDE），DEB 用 `cargo-deb`，RPM 用 `cargo-generate-rpm`，Windows 复用 上游已有 wix/NSIS 打包基建改造。

**Q6.4 中文 IME？**
→ 推荐：M3 专项测试 fcitx5 预编辑/候选窗定位（egui 0.34 已改善 IME，但自绘编辑器仍是翻车高发区），预留 2–3 天缓冲。

**Q6.5 代码审查怎么做（上游 100% AI 生成）？**
→ 推荐：M0 用 2–3 天只读审查三条关键路径——编辑器内核（RenderedEditSession/undo）、渲染缓存（blake3 AST cache + 视口裁剪）、配置持久化。产出审查报告（问题清单 + P0–P3 分级），P0/P1 问题在进入 M2 前修完。
