## P1-01 正文所有权与操作级撤销

**现状**

- 修订号（`content_version`）已驱动 Raw 编辑器同步、撤销快照、AST/Mermaid/小地图缓存，滚动不再全文哈希。
- 但 `Tab.content: String` 仍存在（`src/state.rs:1237`），Raw 编辑器仍持有 Rope；Raw 编辑后整篇转回 String（`src/editor/widget.rs:769`），并按提交做全文 diff。
- 即“单一写入口 + 修订号”已成立，“单一正文载体”尚未成立。

**遗留工作**

1. 引入 `Document`/`EditorSession`，由 `Document` 持有唯一可变 Rope；`Tab` 只保留 ID、路径、视图元数据与修订号。
2. Raw/Rendered/格式化/查找替换/外部重载统一经文档 API 写入。
3. 撤销改为编辑器上报操作（或增量 diff），不再依赖整篇快照与全文 `to_string`。
4. 在性能测量证明必要时，移除 `Tab.content` 第二副本。

**验收**

- 输入一个字符不产生全文 `to_string`、全文克隆或全文哈希。
- 代码搜索中不存在绕过文档 API 的 `tab.content = ...` 写入。
- 大文件输入延迟与内存增量不随文档总长度线性增长。

## P1-04 `state.rs` 状态聚合体

**现状**

- `src/state.rs` 约 8,137 行，仍同时承载标签、编辑器模型、设置、UI 状态、工作区、持久化、恢复与多光标。
- 前面的所有权、恢复和生命周期问题都与这个可变根有关。

**遗留工作**

按变化原因拆分，不做通用 service/repository 层：

- `Document`：正文、路径、编码、磁盘锚点、修订号。
- `EditorSession`：Rope、光标/选区、撤销、折叠、视口。
- `WorkspaceState`：文件树、索引、监听、工作区设置。
- `UiState`：对话框、面板、提示与瞬时交互。
- `SessionCoordinator`：唯一的启动恢复与周期快照协调器。

**验收**

- `state.rs` 只保留聚合与 API，不再直接实现上述领域逻辑。
- 纯逻辑（坐标、多光标、折叠）可独立测试。
- 不要求拆 crate。

## P2-01 崩溃恢复仍在 UI 线程序列化

**现状**

- `save_recovery_content` 已按标签修订号增量写入，未变化标签跳过（`src/state.rs:4830`）。
- 但序列化仍发生在 UI 线程；`capture_session_state` 仍对未修改标签全文哈希（`src/state.rs:4765`）。
- 调用链：`src/app/mod.rs:796` → `capture_session_state` / `save_recovery_content`。

**遗留工作**

1. 生成不可变快照后交给单写后台线程，UI 线程不执行 JSON 序列化与写盘。
2. 为干净标签缓存内容哈希（按 `save_version`/`content_version`），避免每 5 秒全文扫描。
3. 恢复写失败有可见状态；临时文件采用唯一名称。

**验收**

- 15 MB 文档编辑 5 秒，UI 帧不因恢复写盘阻塞。
- 无内容变化的标签在周期快照中不产生全文哈希与重写。

## P2-03 工作区索引事件风暴

**现状**

- 已有 `Arc<AtomicBool>` 取消令牌，切换工作区或 reset 时旧遍历会退出（`src/workspaces/file_index.rs:110`）。
- 文件创建/删除/保存仍逐次 `invalidate()`，下一帧立即启动新一轮索引（`src/app/file_ops.rs:1078`）；没有 debounce/合并。

**遗留工作**

1. 文件事件 300–500 ms debounce/coalesce，一次重建覆盖一批事件。
2. 单 worker + JoinHandle；旧 generation 结果丢弃，线程数量有上限。
3. 索引文件数与内存设上限，UI 显示进度。

**验收**

- 保存大量文件或快速切换工作区时，同时最多一个活动索引 worker。
- 10,000 文件构建期间旧任务可取消，无重复遍历。

## P2-05 工作区信任与布局上限

**现状**

- 终端布局默认不再自动加载（`src/config/settings.rs:2707`），HTML 活动内容默认关闭（`src/export/html_options.rs:91`）。
- 仍没有“首次打开不可信工作区”的信任提示；`terminal_layout.json` 没有叶子数量/大小上限。

**遗留工作**

- 首次打开工作区时询问是否信任并允许自动加载终端布局；记住选择。
- 对布局 schema 限制叶节点数量与文件大小，超限拒绝并提示。

**验收**

- 打开不可信仓库不会自动创建大量终端或加载异常布局。
- 信任后可正常恢复，撤销信任可停止自动加载。

## P3-01 配置“备份”语义

**现状**

- `save_config` 先写 `config.json.bak`，随后 rename 覆盖 `config.json`（`src/config/persistence.rs:286-292`）；成功后所谓备份消失。

**遗留工作**

- 要么保留上一版配置（不 rename 覆盖），要么把 `.bak` 改名为 `.tmp` 并明确“临时文件”语义。
- 按需增加文件与目录 fsync。

**验收**

- 配置保存成功后仍能取到上一版配置，或文档明确说明不保留备份。
- 崩溃窗口内不会留下被误认为有效备份的旧文件。

---

## P3-02 会话/恢复写缺少耐久性

**现状**

- 会话、逐标签恢复、自动保存写均只保证 rename，未 `sync_all`；临时文件名固定为 `.tmp`。

**遗留工作**

- 临时文件写完后 `sync_all`，rename 后对目录 fsync（可选耐久模式）。
- 临时文件使用唯一名称，避免并发/残留冲突。

**验收**

- 掉电/强杀后恢复文件要么完整可读，要么不存在，不出现半写 JSON。
- 多次并发保存不互相覆盖临时文件。

## P3-04 PDF 主线程解析

**现状**

- `open_pdf_tab` 同步 `std::fs::read` 并解析整篇以取得页数（`src/state.rs:4097`）；首次显示与缩放仍在主线程。

**遗留工作**

- 后台解析元数据，首帧先显示占位/进度。
- 页面渲染放入可取消任务，限制缓存页数与像素尺寸。

**验收**

- 大 PDF 打开时 UI 不阻塞；取消/关闭标签后旧渲染任务不再产生可见影响。
- 页面缓存有明确上限。

## 建议顺序

1. P2-01、P2-03：改动小，直接改善恢复与工作区响应。
2. P3-01、P3-02：耐久性小修，补齐配置/恢复语义。
3. P1-01：按“单一写入口 → 操作级撤销 → 移除第二副本”分阶段推进。
4. P1-04：长期结构收敛，跟随 P1-01 的边界逐步拆分。
5. P3-04、P2-05：按大 PDF / 不可信工作区需求排期。

每一项验收通过后，从本文删除对应条目；全部清空后可直接删除本文件。
