> 基线：`v0.6.0`（2026-11-09 核对）  
> 来源：2026-10-24《设计缺陷评估报告》。已删除闭环项与历史论证，仅保留仍需跟踪的遗留项。  
> 本轮（0.6.0）新关闭：P2-01、P2-03、P3-01、P3-02，以及 P1-01 的第一步（Raw 操作上报）。  
> 已闭环、不再展开：P1-02、P1-03、P2-02、P2-04，P2-05 的安全默认值，P3-03 的字节阈值。

## 本轮修改记录（0.6.0）

| 项目 | 处理 | 关键实现 |
|---|---|---|
| P3-02 会话/恢复写耐久性 | **已关闭** | session、逐标签 recovery、autosave 统一改用 `files::atomic::write_atomic`：临时文件 + `sync_all` + rename + 目录 fsync + 唯一临时名 |
| P3-01 配置备份语义 | **已关闭** | `save_config` 先将上一版 `config.json` 原子写入 `config.json.bak`，再原子替换 `config.json`；备份不再消失 |
| P2-01 恢复写阻塞 UI | **已关闭** | 新增 `RecoveryWriter` 单写线程；UI 线程只捕获元数据与变化正文，JSON 序列化/fsync/写盘在后台；干净标签内容哈希按 `content_version` 缓存 |

## P1-01 正文所有权（剩余部分）

**已完成**

- 修订号驱动 Raw 编辑器同步、撤销快照、AST/Mermaid/小地图缓存。
- Raw 编辑由 `TextBuffer` 记录操作，`EditorWidget` 重放到 `Tab.content` 并写入 `EditHistory`；不再每键全文转换与 diff。
- Raw 不再调用每帧撤销快照。

**遗留**

1. `Tab.content: String` 仍是第二副本；`Tab`、`MDOxideEditor`、撤销历史各自持有正文视图。
2. 需要引入 `Document`/`EditorSession`：`Document` 持有唯一可变 Rope，`Tab` 只保留 ID、路径、视图元数据与修订号。
3. 渲染、格式化、查找替换、外部重载、会话恢复统一通过文档 API 写入。
4. 在 profiling 证明必要时移除 `Tab.content`。

**验收**

- 代码搜索中不存在绕过文档 API 的 `tab.content = ...` 写入。
- 任意模式编辑都不产生全文 `to_string`、全文克隆或全文哈希。
- 大文件输入延迟与内存增量不随文档总长度线性增长。

## P1-04 `state.rs` 状态聚合体

**现状**

- `src/state.rs` 仍约 8,000 行，同时承载标签、编辑器模型、设置、UI 状态、工作区、持久化、恢复与多光标。
- P1-01 的文档边界稳定后，才能安全拆分。

**遗留工作**

- `Document`：正文、路径、编码、磁盘锚点、修订号。
- `EditorSession`：Rope、光标/选区、撤销、折叠、视口。
- `WorkspaceState`：文件树、索引、监听、工作区设置。
- `UiState`：对话框、面板、提示与瞬时交互。
- `SessionCoordinator`：唯一启动恢复与周期快照协调器。

**验收**

- `state.rs` 只保留聚合与 API，不再直接实现上述领域逻辑。
- 纯逻辑（坐标、多光标、折叠）可独立测试。
- 不要求拆 crate。

## P2-05 工作区信任与布局上限

**现状**

- 终端布局默认不自动加载；HTML 活动内容默认关闭。
- 仍没有“首次打开不可信工作区”的信任提示；`terminal_layout.json` 没有叶子数量/大小上限。

**遗留工作**

- 首次打开工作区询问是否信任并允许自动加载终端布局，记住选择。
- 对布局 schema 限制叶节点数量与文件大小，超限拒绝并提示。

**验收**

- 打开不可信仓库不会自动创建大量终端或加载异常布局。
- 信任后可正常恢复，撤销信任可停止自动加载。

---

## P3-04 PDF 主线程解析

**现状**

- `open_pdf_tab` 同步 `std::fs::read` 并解析整篇以取得页数；首次显示与缩放仍在主线程。

**遗留工作**

- 后台解析元数据，首帧先显示占位/进度。
- 页面渲染放入可取消任务，限制缓存页数与像素尺寸。

**验收**

- 大 PDF 打开时 UI 不阻塞；取消/关闭标签后旧渲染任务不再产生可见影响。
- 页面缓存有明确上限。

---

## 建议顺序

1. P1-01 第二步：把正文所有权收敛到 `Document`/`EditorSession`，再移除 `Tab.content`。
2. P1-04：跟随 P1-01 的边界增量拆分 `state.rs`。
3. P2-05、P3-04：按不可信工作区 / 大 PDF 需求排期。

每一项验收通过后，从本文删除对应条目；全部清空后可直接删除本文件。
