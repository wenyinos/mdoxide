### 本轮踩坑记录

- `Tab` 结构体尾部残留的孤立文档注释触发 `E0585`，rustc 会把该结构体恢复为错误类型，导致所有字段访问被推断成 `Option<Path>` / `Option<str>` 等 unsized 类型。清掉悬空注释后这类报错全部消失。
- `Tab` 实现 `Deref` 后，`&mut tab.content` 会借用整个 `*tab`，不能再与 `tab.id` 等字段读并行。渲染编辑器构造处改为复用已保存的 `tab_id`。
- 同一 `Document` 内两个字段同时可变借用（如 `edit_history` 与 `content`）必须写成 `self.document.field`，不能分两次走 `DerefMut`。

## P1-01 正文所有权（剩余部分）

**已完成**

- 修订号驱动 Raw 编辑器同步、撤销快照、AST/Mermaid/小地图缓存。
- Raw 编辑由 `TextBuffer` 记录操作，`EditorWidget` 重放到 `Tab.content` 并写入 `EditHistory`；不再每键全文转换与 diff。
- Raw 不再调用每帧撤销快照。
- `Document` 成为正文、路径、编码、磁盘锚点、撤销历史与修订缓存的唯一状态层所有者。
- `Tab` 不再声明 `content`/`original_content`/`path`/`content_version`/`source_epoch`/编码等字段；`tab.content` 等调用点经 `Deref`/`DerefMut` 转发到 `document`，构造与恢复路径统一填充 `Document`。

**遗留**

1. `Document.content` 仍是 `String`；Raw 编辑器的 `TextBuffer` 仍持有一份 Rope。二者通过操作重放保持一致，但还不是“唯一 Rope”。
2. 渲染、格式化、查找替换、外部重载仍通过 `tab.content` 的 `DerefMut` 直接赋值，没有统一的文档写入 API；跨模块写入的修订号/撤销边界依赖调用方自觉。
3. 大文件输入延迟与内存增量尚未在 profiling 下量化，“不随文档总长度线性增长”未验证。

**验收（未全部满足）**

- 代码搜索中不存在绕过文档 API 的 `tab.content = ...` 写入。（未满足：`DerefMut` 仍允许直接赋值）
- 任意模式编辑都不产生全文 `to_string`、全文克隆或全文哈希。（Raw 已满足；渲染/格式化路径未逐项核对）
- 大文件输入延迟与内存增量不随文档总长度线性增长。（未测量）

## P1-04 `state.rs` 状态聚合体

**现状**

- `src/state.rs` 已从约 8,246 行降到 4,841 行，只保留 `AppState`、`FileType`、文本坐标helper 与少量聚合逻辑。
- 已拆出的领域模块：
  - `src/state/document.rs`：`Document`、`Tab`、`TabKind`/`TabContent`、特殊标签页、图片/PDF 查看器状态、标签构造与视图方法。
  - `src/state/editor_session.rs`：`Selection`、`MultiCursor`、`TransientHighlight`、`FoldKind`/`FoldRegion`/`FoldState` 及文本坐标转换。
  - `src/state/ui_state.rs`：`UiState`、`PendingCodeRun`、`SavePromptContext`、`PendingAction`。
  - `src/state/workspace.rs`：`BacklinkEntry`/`BacklinkIndex`、链接提取与文件名归一化。
- 父模块通过 `pub use` 重导出，外部 `crate::state::Tab` 等路径不变。

**遗留工作**

- `WorkspaceState`：`AppState` 仍直接持有 workspace/watcher/pending events，并实现其生命周期逻辑，尚未收敛为独立类型。
- `SessionCoordinator`：启动恢复、周期快照、冲突解析仍是 `impl AppState` 方法，未独立。
- `EditorSession`：选区/折叠类型已拆出，但 Rope、光标、视口仍分散在 `Tab` 与编辑器 widget。
- `FileType` 与文本坐标 helper 仍留在 `state.rs`，可后续并入 document/editor_session。

**验收**

- `state.rs` 只保留聚合与 API，不再直接实现上述领域逻辑。（部分满足）
- 纯逻辑（坐标、多光标、折叠）可独立测试。（已满足：`editor_session.rs` 内聚）
- 不要求拆 crate。

## P2-05 工作区信任与布局上限

**现状**

- 终端布局默认不自动加载；HTML 活动内容默认关闭。
- 仍没有“首次打开不可信工作区”的信任提示；`terminal_layout.json` 没有叶子数量/大小上限。

**遗留工作**

- 首次打开工作区询问是否信任并允许自动加载终端布局，记住选择。
- 对布局 schema 限制叶节点数量与文件大小，超限拒绝并提示。

**验收**

- 打开不可信仓库不会自动创建大量终端或加载异常布局。
- 信任后可正常恢复，撤销信任可停止自动加载。

## P3-04 PDF 主线程解析

**现状**

- `open_pdf_tab` 同步 `std::fs::read` 并解析整篇以取得页数；首次显示与缩放仍在主线程。

**遗留工作**

- 后台解析元数据，首帧先显示占位/进度。
- 页面渲染放入可取消任务，限制缓存页数与像素尺寸。

**验收**

- 大 PDF 打开时 UI 不阻塞；取消/关闭标签后旧渲染任务不再产生可见影响。
- 页面缓存有明确上限。

## 建议顺序

1. P1-01 收尾：若 profiling 证明必要，把 `Document.content` 与 Raw `TextBuffer` 统一为单一 Rope；在此之前先把跨模块正文写入收敛到文档 API，堵住 `tab.content = ...`。
2. P1-04：把 `AppState` 的会话恢复/工作区生命周期方法拆成 `session.rs`/`workspace_state.rs` 的 `impl AppState` 块。
3. P2-05、P3-04：按不可信工作区 / 大 PDF 需求排期。

每一项验收通过后，从本文删除对应条目；全部清空后可直接删除本文件。
